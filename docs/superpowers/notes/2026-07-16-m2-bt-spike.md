## 1. 自定义节点作者模式(已编译验证 ✅)

通过反射 `Unity.Behavior` 程序集 + 编译 `Assets/Scripts/CitizenSim/Behavior/BtNodeSpikes.cs` 确认。

### 自定义 Action

```csharp
using Unity.Behavior;
using Unity.Properties;
using UnityEngine;

namespace CitizenSim
{
    [System.Serializable]                       // 见下方"坑 1":不要用 using System;
    [GeneratePropertyBag]                       // Unity.Properties,源生成器,生成属性袋
    [NodeDescription("名字", "描述", "故事")]    // 暴露特性,ctor 8 参全可选
    public class MyAction : Action              // Action : Node,abstract
    {
        // 字段会被图编辑器/黑板序列化(public 字段即可)
        public float SomeField = 1f;

        protected override Status OnStart()  { return Status.Success; }  // 见下方 Status
        protected override Status OnUpdate() { return Status.Success; }
        protected override void  OnEnd()     { }
    }
}
```

### 自定义 Condition

```csharp
    [System.Serializable]
    [GeneratePropertyBag]
    [Condition("名字", "描述", "故事")]          // 暴露特性,ctor 6 参全可选
    public class MyCondition : Condition        // Condition 基类是 object(非 Node!)
    {
        public override bool IsTrue() => true;  // public override(非 protected)
        // 可选:public override void OnStart() {} / OnEnd() {}
    }
```

### 暴露特性(决定性发现)

反射所有内置节点发现:**没有 `[NodeInfo]`/`[NodeCategory]`**(全程序集搜不到)。真实暴露机制:
- **Action 节点**用 `[Unity.Behavior.NodeDescription]`
- **Condition 节点**用 `[Unity.Behavior.Condition]`
- 两者都配 `[System.Serializable]` + `[Unity.Properties.GeneratePropertyBag]`

ctor 参数(全有默认值,可省略):
- `NodeDescription(string name="", string description="", string story="", string icon="", string category="", string id="", bool hideInSearch=false, string filePath="")`
- `Condition(string name="", string description="", string story="", string category="", string id="", string filePath="")`

### override 钩子签名(反射 NonPublic DeclaredOnly 确认)

- `Node`(Action 继承自它):
  - `protected virtual Status OnStart()` / `OnUpdate()` -> 返回 `Node.Status`
  - `protected virtual void OnEnd()` / `OnSetup()` / `OnTeardown()`
- `Condition`(基类 object,独立体系):
  - `public abstract bool IsTrue()` -> `public override bool IsTrue()`
  - `public virtual void OnStart()` / `OnEnd()` -> `public override void`

### Status 枚举(`Unity.Behavior.Node+Status`)

```
Uninitialized=0  Running=1  Success=2  Failure=3  Waiting=4  Interrupted=5
```
Action 子类内可简写 `Status.Success`(继承自 `Node` 的嵌套类型,简单名可解析--前提是 `Action` 基类无歧义,见坑 1)。

### `GameObject` 属性

- `Action`(经 `Node`)与 `Condition` 都有 `public GameObject GameObject { get; }`,返回 agent 挂载的 GO。Condition/Action 内用 `GameObject.GetComponent<CitizenAuthoring>()` 读市民数据。

### 坑 1:`using System;` 与 `Unity.Behavior.Action` 冲突

`System.Action`(委托)与 `Unity.Behavior.Action`(BT 节点基类)同名。**Behavior 节点文件不要写 `using System;`**,改用 `[System.Serializable]`(`System.` 前缀不需 using)。否则 `Action` 歧义会连带导致继承自 `Node` 的 `Status` 无法解析。

### asmdef 改动

`CitizenSim.asmdef` 的 `references` 已加 `"Unity.Behavior"`。`Unity.Properties`(`[GeneratePropertyBag]`)经 `UnityEngine` 程序集可用,无需额外引用。

### 编辑器节点菜单出现性

节点暴露靠上述特性,与内置节点特性完全一致 -> **按特性对等原则应出现在 Behavior 编辑器节点菜单**。最终可视确认在 Task 6 建图时验证(若不出现,排查特性名/`[GeneratePropertyBag]` 源生成器)。

## 2. Tick 机制:Design A(手动 `Graph.Tick()`)--反射确认可行 ✅

### 反射确认的事实

`BehaviorGraphAgent`(MonoBehaviour)声明的方法/字段:
- 生命周期:`Awake` / `Init` / `Start` / `Update` / `End` / `Restart` / `OnDestroy`
- **无 `OnEnable` / `OnDisable`** -> 禁用 agent 不会触发图的 End/Start,图状态保持
- 字段:`m_Graph`(运行时图实例)、`m_OriginalGraph`、`m_IsInitialised`、`m_IsStarted`
- 属性 `Graph`(返回 `m_Graph`)、`BlackboardReference`

`BehaviorGraph`(ScriptableObject):
- `public void Start()` / `public void Tick()` / `public void End()` / `public void Restart()`
- 属性 `IsRunning`、`BlackboardReference`

### Design A 结论(主方案)

`BehaviorGraphAgent.Update()` 是自动 tick(每帧调 `Graph.Tick()`)。Unity 约定:禁用的 MonoBehaviour 不调 `Update`,但 `Awake` 仍跑(GO 激活时)。无 `OnDisable` -> 禁用不 End 图。

**调度器初始化序列(稳定):**
1. Bootstrap 生成 citizen GO,挂 `BehaviorGraphAgent`,**初始 enabled = true**。
2. 让 Unity 自然跑 `Awake`(Init)+ `Start`(`Graph.Start()`,置 `m_IsStarted=true`)。
3. `BtScheduler` 首帧 `Update` 里把所有 agent `enabled = false`(停止自动 tick;图保持 started)。
4. 此后调度器每帧 round-robin 选 ~N 个 agent,调 `agent.Graph.Tick()` 手动求值。

**M4 威胁插队**:被 `Threatened` 标记的 agent 可在任意帧额外调 `Graph.Tick()`(跳过分片节流),不受 round-robin 限制。这是选 Design A 而非 Design B 的主因。

### Design B(退路,若 Play 实证 A 失败)

round-robin 启用/禁用 agent:每帧 enable ~N 个 agent(它们 `Update` 自动 tick 一次),disable 其余。无需手动 `Tick()`。缺点:威胁插队需 dedup(被插队的 agent 可能也在轮转里),不如 A 干净。

### 未做的实证(留 Task 7/8)

反射证据强(`Tick` 公开、无 OnEnable/OnDisable、`Update` 是唯一自动 tick),但**未跑 Play 模式实测** `agent.enabled=false` + 手动 `Graph.Tick()` 是否真求值。Task 7 实现调度器、Task 8 验收 Play 时即实证;若失败切 Design B。无需为 spike 单独造图资产(程序化造图复杂,不值当)。

## 3. 对 M2 计划的回填

Task 5(IsHungry/SetGoal)、Task 7(调度器)代码以此结论为准:
- 节点用 `[System.Serializable]`+`[GeneratePropertyBag]`+`[NodeDescription]`/`[Condition]`,**不要 `using System;`**。
- Action override:`protected override Status OnStart/OnUpdate`,返回 `Status.Success/Running/Failure`;`OnEnd` 返回 void。
- Condition override:`public override bool IsTrue()`;用 `GameObject.GetComponent<CitizenAuthoring>()` 读需求。
- 调度器走 Design A:init 后禁用 agent,手动 `agent.Graph.Tick()` round-robin;M4 威胁插队额外 tick。
